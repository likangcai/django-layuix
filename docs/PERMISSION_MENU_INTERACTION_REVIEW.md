# 权限管理与菜单管理交互对标评审

作者：影子（Yingzi）　版本：v1.0　日期：2026-11-26

## 1. 结论（TL;DR）

【事实】参考项目没有独立的“权限管理”页面；权限管理入口是角色列表的“角色权限”按钮，打开 zTree 授权弹窗。菜单管理是独立树表页面，提供名称搜索、全部展开、全部折叠、图标选择器和按钮权限穿梭。
【判断】参考项目更统一的原因不是 Layui 版本，而是用公共组件约束了弹窗、表格、树表、提示和批量操作；当前项目应补齐交互骨架，而不是照搬页面级样式。
【事实】当前项目功能更完整，已有权限目录、授权树搜索/回显、父节点半选、按钮权限目录和数据范围；但权限总览菜单路径未映射到静态页面，属于 P0 可达性缺陷。
【判断】本期优先修复入口映射，并把菜单管理的“搜索 + 全部展开 + 全部折叠”对齐参考项目；授权树组件化和角色批量操作列为后续迭代。
【待确认】是否把按钮权限从菜单表单穿梭改为独立权限目录管理。
【待确认】是否把角色数据范围选择并入授权弹窗，而不是停留在角色表单文本面板。
【待确认】是否把角色行内状态切换和批量删除纳入下一期。

## 3. 参考项目交互事实

### 3.1 权限管理

【事实】角色列表页操作列提供“角色权限”按钮，点击后用 `admin.open` 弹出授权窗。
【事实】授权窗用 zTree 的 `check.enable` 和 `simpleData` 渲染权限树，默认展开全部节点；保存时只提交显式勾选节点，半选父节点不入库。
【事实】服务端先查全部菜单，再按角色已有关系设置 `checked`，下次打开直接回显；保存时先删旧关系再逐条创建。
【事实】权限分两层：菜单权限由 `type=0` 菜单的 permission 决定，按钮权限由 `type=1` 菜单节点决定；参考项目没有数据权限配置 UI。
【判断】可借鉴的是“服务端下发 checked 状态 + 显式勾选节点保存”的契约，不应借鉴“先删后建”的非事务写法。

### 3.2 菜单管理

【事实】菜单页使用树表，不是普通表格；顶部提供菜单名搜索、全部展开、全部折叠和新增菜单。
【事实】行操作有编辑、删除、添加子级；点击行节点即打开编辑弹窗。
【事实】表单包含上级菜单下拉、图标选择器、排序、显示状态，以及按钮权限穿梭框。
【事实】按钮权限按模板动作批量生成，参考实现会先删旧节点再重建；当前项目已有更安全的幂等生成逻辑，不应回退。
【判断】最值得直接落地的是查询区三件套与公共弹窗约束；按钮权限生成链路保留当前项目实现。

## 4. 当前项目差异

| 维度 | 参考项目 | 当前项目 | 结论 |
|---|---|---|---|
| 权限入口 | 角色列表按钮打开授权弹窗 | 角色页有授权弹窗，另有权限总览页 | 当前更强，但权限总览入口映射缺失 |
| 授权树 | zTree 默认展开，父子联动，服务端 checked | Layui tree + 手工半选 + 精确回显 + 搜索 | 当前功能更细，但实现分散，应组件化 |
| 保存策略 | 先删后建，非事务 | 事务化并校验可授权菜单 | 当前更优，保留 |
| 菜单列表 | 树表 + 搜索 + 展开/折叠 | 左树 + 右扁平表，无树搜索与展开折叠 | 本期补齐 |
| 菜单表单 | 上级、图标、排序、状态、按钮穿梭 | 已有同类能力，按钮权限更动态 | 保持 |
| 批量操作 | 角色有批量删除，菜单无 | 角色与菜单均无批量 | 后续迭代 |
| 状态切换 | 角色列表行内 switch，菜单列表状态徽章 | 角色与菜单列表均徽章 | 后续迭代 |
| 公共层 | 模板标签 + func/common/admin 三层封装 | `LayuiUI.table/dialog` + `DataAdmin` + 页面级脚本 | 方向一致，但页面级重复仍多 |
