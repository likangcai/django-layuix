# 1.6.0 软件生命周期评审报告

作者：影子（Yingzi）　版本：v1.0　日期：2026-11-26

## 1. 结论（TL;DR）

【事实】本轮完成街道/乡镇数据、用户多岗位、权限目录页面与目录权限码数据库唯一键。
【判断】地区数据从“省市县”扩展到“省市县街道”后，列表改为服务端分页、树独立加载，避免 4 万级数据拖慢页面。
【事实】用户主岗与兼任岗位分离，兼容原 `position_id` 接口，同时新增 `position_ids` 与 `position_names`。
【事实】权限目录页展示 322 项页面/按钮权限，核心权限不可停用。
【待确认】是否继续扩展到村/社区级数据。
【待确认】是否恢复 Excel 格式导入导出。
【待确认】是否为岗位任职增加有效期、主岗变更历史。

## 3. 实现记录

### 3.1 街道/乡镇数据

- 新增 `django_layuix/rbac/data/china_streets.json`，40842 条街道/乡镇。
- 地区总数据量 44056 条：省 34、地 333、县 2847、街道 40842。
- 街道文件与民政部省市县基础文件分离，官方更新脚本不会覆盖街道层。
- 新增 `scripts/update_streets_from_npm.py`，从 `china-division` 数据包刷新街道种子。
- `load_regions` 默认合并基础种子与街道种子，新增 `--skip-streets` 开关。
- 修复 44k 编码回查触发 SQLite 变量上限的问题。
- 地区列表新增服务端分页 `page` / `page_size`，新增 `/regions/tree/` 树接口。
- 地区页改为服务端分页，树只加载省、市和直辖市县区。
- 地区接口分页响应约 0.14 秒，树接口约 0.09 秒。

### 3.2 用户多岗位

- `UserProfile` 新增 `positions` 多对多关系，保留 `position` 主岗。
- 用户创建/更新支持 `position_ids` 列表，兼容原 `position_id`。
- 用户列表返回 `position_ids`、`position_names`，并预取兼任岗位。
- 用户新增/编辑弹窗增加“主岗”和“兼任岗位”多选。
- 主岗自动计入兼任岗位；清空多岗位同步清空主岗。
- 字段白名单加入多岗位字段。
- 岗位删除时主岗置空、兼任关系自动移除，不删除用户。

### 3.3 权限目录

- 新增 `/static/layui/pages/permission.html` 权限总览页。
- 新增 `permission:view` / `permission:edit` 权限码。
- 新增权限目录 API：
  - `GET /admin/api/rbac/permission-catalog/`
  - `POST /admin/api/rbac/permission-catalog/<id>/status/`
- 页面展示权限总数、页面权限数、按钮权限数、授权角色数和启停状态。
- `permission:view`、`permission:edit` 为受保护权限，禁止停用。
- 侧栏新增“权限管理 → 权限总览”。

### 3.4 目录唯一键

- `Menu` 新增 `catalog_key` 字段，内置权限目录行写入 `permission_catalog:<code>`。
- 通过数据库唯一键保证目录权限码唯一；其他业务节点 `catalog_key` 为 NULL，保留同码业务节点兼容。
- 迁移 `0018_menu_catalog_key` 先加字段、回填、再加唯一约束，兼容历史重复数据。
- `register_page_permissions` 会补写缺失的唯一键。

### 3.5 工具栏与字段白名单审计

- 所有表格型管理页已具备参考式表格工具栏。
- 权限页补齐统计卡、筛选栏、分页和受保护操作状态。
- 现有字段白名单覆盖 RBAC 用户、角色、日志、配置、运维服务器、商城与数据管理模块；手工 payload 页面继续使用显式字段。
